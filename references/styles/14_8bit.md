# 14 · 8-bit pixel game (NES-era console graphics, mid-1980s)

**Status:** Built ★★★
**Layer:** Material (works on any subject)
**Web fit:** High for playful product UIs, gamified progress, onboarding, landing pages and easter-egg themes; Medium for everyday tools (works if body text stays readable). Low for long-form reading and data-dense tables at small sizes.
**Mockup:** `assets/mockups/14_8bit.png`

## Recognisable traits

- A coarse, visible pixel grid: the source draws at 240×135 and scales ×8, so one "pixel" is a hard 8px square with no anti-aliasing.
- A small fixed palette (14 colours for characters in the source) chosen from NES-like hues; gradients exist only as two-colour checkerboard dithering.
- 1px black outline around each sprite part, drawn per part so faces, hair and arms keep inner contours.
- Stepped motion: a few poses swapped at 8–15fps, objects moving in whole pixels.
- Game-screen furniture: HUD text in a pixel font, hearts, coins, "?" blocks, black dialog boxes with a white double line.

## Typography

Labels and headings: **Press Start 2P** (`"Press Start 2P", ui-monospace, monospace`) at 8–12px for UI labels, uppercase, tracking 0, line-height ~1.5–1.7; headings with a 2px hard text shadow. In the source HUD, 48px meant one font pixel = 6 screen pixels; 64px was too wide and collided with icons, so size pixel fonts in integer multiples of their 8px grid. Body: **VT323** (`"VT323", ui-monospace, monospace`) runs small, so step body up to ~20px (the app maps Tailwind sizes up: base 20px, sm 18px, xs 16px). Turn off font smoothing for the pixel faces (`-webkit-font-smoothing: none`).

## Surfaces, texture and edges

- **Dialog boxes without images:** stacked `box-shadow`s give a black window with a white inner line, a black frame drawn only along the axes (so corners stay notched) and a hard offset shadow:
  ```css
  .box { background: #000; color: #fcfcfc; border: 0; box-shadow:
    inset 0 0 0 3px #000, inset 0 0 0 5px #fcfcfc,
    0 -3px 0 #000, 0 3px 0 #000, -3px 0 0 #000, 3px 0 0 #000,
    7px 7px 0 var(--shadow); }
  ```
- **Sprites from string bitmaps:** one character per pixel (`"."` clear), converted to a tiny SVG with one `<rect>` per run of same-coloured pixels, then handed to CSS as a `data:` URL custom property. Always render with `image-rendering: pixelated` and sizes in integer multiples.
- **Backgrounds (source):** a cross-stitch wall on a 6px grid (3×3 crosses, alternate rows offset 3px); bricks 16×6 with 1px mortar, alternate rows offset 8, one row of `#fbe2a6` highlight on top and left; floor planks with a black seam every 24px. Pre-render as a small PNG/SVG tile and repeat it.
- **Dithered gradients:** where two bands meet, a ±0.05 strip of `(x + y) % 2` checkerboard. In CSS: `conic-gradient(#a 25%, #b 0 50%, #a 0 75%, #b 0) 0 0 / 2px 2px` scaled to the pixel size.

## Shapes and layout

`border-radius: 0` on everything. Lines are 2–3px (one or more whole pixels), never hairlines. Shadows are hard offsets (7px in the app), never blurred. Align spacing to the pixel unit (suggested 4px or 8px). Layout reads as a game screen: a sky page, a HUD strip on top (counters, hearts, coins), content in dialog boxes, a sidebar as a pause menu.

## Components

- **Buttons:** gold fill, black text, a hard dark-gold `#ac7c00` bottom/right shadow; on `:active` the button drops into its shadow (translate 2–3px, shadow 0).
- **Cards / panels:** black RPG dialog boxes; on hover or focus the white inner line turns gold.
- **Navigation:** a pause menu in Press Start 2P 9px; the active item shows a blinking ▶ cursor sprite (`animation: blink 1s steps(1) infinite`) instead of a highlight bar.
- **Inputs:** black box, white line, a blinking block caret; focus outline 3px gold with 3px offset.
- **Chat:** agent replies in a dialog box like RPG text; user messages in a smaller white box.
- **Badges:** pixel tags (8px font, 2px border).
- **Icons:** 8×8 or 16×16 bitmaps (hearts, coins, "?" block, mascot head) drawn crisp.
- **Loading:** a "?" block bumping and popping a coin (stepped), or dots cycling `"" → "." → ".." → "..."` via `content` keyframes. Spinners rotate in `steps(8)`.
- **Credits / limits:** hearts or a coin counter in the HUD; a blinking empty heart when low.
- **Mascot:** a 16×16 sprite with a blink frame swapped every few seconds (`steps(1)`), outlined in 1px black per part.

## Motion

- Everything steps; nothing eases. The app sets `transition: none` and `animation-timing-function: steps(4, end)` globally for the look, and own animations declare their step counts.
- Source loops (8–15fps feel): a tail cycling four poses `[-0.55, 0, 0.55, 0]` at 15fps; a plant jittering in whole pixels `[0, 1, 0, -1]`; a "?" block raising a coin 9 low-res pixels in a half-sine then dropping; clouds moving 1px every 2 frames; steam as three columns of 1×2 dots rising 1px per frame, looping every 6px; HUD heart flashing every 2 frames.
- UI mapping: idle (clouds drifting `steps(360)` over 90s, stars twinkling `steps(1)`), hover (gold line or ▶ cursor), thinking (block bump + coin pop), done (coin rises with a "+1", `steps(8)`), entrance (boxes appear in 2–3 steps, no fades).
- `prefers-reduced-motion`: `animation: none` on everything and hide decorative pops; blinking cursors become static.

## Techniques

- **Low-res draw, nearest-neighbour upscale:** for canvas art, draw at 1/8 size and `drawImage` up with `imageSmoothingEnabled = false`. For DOM, render sprites as SVG rects or PNGs with `image-rendering: pixelated`.
- **Spriteize a vector illustration** (to make existing art match): rasterise each part at low res; alpha < 110 → transparent (kills anti-aliasing); quantise the rest to the palette (nearest colour); outline 1px black wherever a transparent pixel has an opaque 4-neighbour. Do it per part (far arm, body, hair, face, fringe, near arm), not once for the whole figure, or the parts merge into one blob. Read non-premultiplied RGBA; don't divide by alpha again.
- **Tiny details by hand:** eyes 1×2, cat eyes 2×2 with a white top-left pixel, nose 1px, blush 2×1. Small objects (a 6px mug) are drawn pixel by pixel; scaled vectors blur at that size.
- HUD and text are drawn at full resolution in a pixel font, not inside the low-res canvas.

## Performance and accessibility

- Cheap: CSS box-shadow frames, data-URL sprites, stepped transforms. Avoid per-frame canvas redraws of the whole page; keep decorations as layered DOM sprites.
- Contrast: white on black 20.5:1, gold on black 11.8:1, black on day sky 12.5:1, `#a81000` on white 7.5:1, muted `#c8d0f0` on the night sky 11.7:1. Pixel fonts are the real risk: keep body in VT323 at ≥18px and use Press Start 2P only for short labels.
- Blinking: keep blink rates ≤ 1–2Hz, never flash large areas, and stop all blinking under reduced motion.

## Pitfalls

- One outline around a whole figure → hair, face and arms merge; outline each part.
- Anti-aliased vector art scaled down → mushy edges; threshold alpha and quantise.
- Pixel font sized off-grid (e.g. 64px when the slot fits 48px) → text collides with icons; use integer multiples.
- Overlaps exaggerated by black outlines (the source's cat head pressing on the windowsill) → leave a pixel of clearance between sprites and frames.
- Soft shadows and rounded corners from the base UI leaking through → reset `box-shadow` and `border-radius` globally for the look.
- Closed off-canvas drawers showing their hard shadow at the screen edge → drop the shadow when hidden.
